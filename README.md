# js100-pathum-traffic-pipeline

โปรเจกต์นี้คือระบบ **Automated Data Pipeline (ETL)** ที่ทำงานแบบอัตโนมัติในการดึงข้อมูล (Web Scraping) สถานการณ์การจราจร อุบัติเหตุ และเหตุฉุกเฉินจากเว็บไซต์วิทยุ จส.100 (JS100) โดยนำข้อมูลมาทำความสะอาด จัดโครงสร้างใหม่ และจัดเก็บลงในฐานข้อมูล เพื่อเตรียมพร้อมสำหรับการนำไปวิเคราะห์ (Data Analytics) หรือสร้าง Dashboard ต่อไป

---

## 🎯 จุดประสงค์ของโครงการ (Objectives)

โครงการนี้ถูกพัฒนาขึ้นมาเพื่อโฟกัสการแก้ปัญหาและติดตามสถานการณ์ใน **"พื้นที่จังหวัดปทุมธานีและเขตรอยต่อ"** โดยเฉพาะ เนื่องจากเป็นโซนที่มีหมู่บ้าน มหาวิทยาลัย และนิคมอุตสาหกรรมหนาแน่น ซึ่งมักจะประสบปัญหาการจราจรติดขัดอย่างหนัก 

จุดประสงค์หลักของการดึงข้อมูลชุดนี้ประกอบด้วย:
* **ติดตามจุดเสี่ยงอุบัติเหตุ:** เพื่อเก็บสถิติว่าบริเวณใดในปทุมธานี (เช่น ถนนพหลโยธิน, รังสิต-นครนายก, คลองหลวง, ลำลูกกา) มีอุบัติเหตุเกิดขึ้นบ่อยที่สุด
* **วิเคราะห์รูปแบบการจราจร (Traffic Pattern):** เพื่อทำความเข้าใจช่วงเวลาที่รถติดหนักในแต่ละวัน หรือผลกระทบจากสภาพอากาศต่อการเดินทางในพื้นที่
* **สร้างศูนย์กลางข้อมูล (Centralized Data):** เปลี่ยนข้อมูลข่าวสารที่เป็นข้อความสั้นๆ บนหน้าเว็บ ให้กลายเป็นฐานข้อมูลเชิงโครงสร้าง (Structured Data) ที่สามารถนำไปใช้ต่อยอดสร้างโมเดลทำนายเส้นทาง หรือระบบแจ้งเตือนประชาชนในพื้นที่ปทุมธานีได้

## ⚙️ โครงสร้างการทำงานของระบบ (How It Works)

ระบบนี้ถูกออกแบบให้ทำงานอัตโนมัติในทุกๆ ชั่วโมง (Hourly Batch Processing) โดยแบ่งการทำงานออกเป็น 3 ขั้นตอนหลัก และควบคุมการทำงานทั้งหมดผ่าน Data Orchestration Tool ดังนี้:

### 1. Extract (การดึงข้อมูล)
* ใช้ **Playwright (Asynchronous)** ในการเปิดเบราว์เซอร์จำลองเพื่อดึงข้อมูลจากเว็บไซต์ JS100
* ระบบจะทำการค้นหาข้อมูลแบบเจาะจงพื้นที่ โดยใช้ Keyword ที่เกี่ยวข้องกับจังหวัดปทุมธานีโดยเฉพาะ เช่น `เมืองปทุมธานี`, `คลองหลวง`, `ธัญบุรี`, `ลำลูกกา`, `รังสิต`, `ถนนรังสิตนครนายก` เป็นต้น
* กรองเฉพาะข้อมูลที่เกิดขึ้นใน **"1 ชั่วโมงที่ผ่านมา"** เท่านั้น เพื่อลดความซ้ำซ้อนและประหยัดทรัพยากรการประมวลผล

### 2. Transform (การแปลงและทำความสะอาดข้อมูล)
* แปลงข้อความวันที่และเวลาภาษาไทย (เช่น "12 มีนาคม 2567") ให้กลายเป็นมาตรฐาน ISO (`datetime`)
* แยกหมวดหมู่ข้อความออกเป็น "ข่าว" และ "ข้อมูลจราจร"
* ลบข้อมูลที่ซ้ำซ้อน (Drop Duplicates) และสร้าง Unique ID (MD5 Hash) จากเนื้อหาและเวลาเพื่อให้ง่ายต่อการจัดการในฐานข้อมูล

### 3. Load (การจัดเก็บข้อมูล)
* นำข้อมูลที่ผ่านการทำความสะอาดแล้ว โหลดเข้าสู่ฐานข้อมูล **PostgreSQL** โดยบันทึกข้อความต้นฉบับ, หมวดหมู่, พื้นที่ที่ค้นพบ และเวลาเกิดเหตุ เพื่อเป็น Data Warehouse สำหรับการดึงไปทำ Visualization ต่อไป

## 🤖 ระบบควบคุมอัตโนมัติ (Orchestration)
โปรเจกต์นี้ควบคุมการทำงานและตั้งเวลา (Scheduling) ด้วย **Prefect** โดยกำหนดให้ Pipeline รันอัตโนมัติใน **นาทีที่ 5 ของทุกชั่วโมง** (Cron: `5 * * * *`) เพื่อคอยดึงข้อมูลความเคลื่อนไหวของชั่วโมงที่ผ่านมาอย่างสม่ำเสมอ โดยไม่ต้องมีคนคอยกดสั่งงาน
